## Purpose

将继承应用转为两名成员能够按同一约束开发、检查、独立启动和交付的团队基线，要求规范可以被实际读取、失败检查能够阻断交付、运行与回滚证据可追溯，并明确个人阶段已验收能力不能替代团队协作的实际验证。

## ADDED Requirements

### Requirement: 团队规范与完整模块责任
仓库 MUST 提供产品、后端、安全、测试、部署运维五类规范，每类明确具体规则、检查方法、缺陷判据及违规处置；常驻规则 MUST 从 `AGENTS.md` 可达，按动作执行的必要技能 MUST 有输入、步骤和产出。成员 A/B MUST 以完整功能模块或开发/测试角色承担责任，MUST NOT 将同一功能的前端、接口和数据分别分配给两人而无完整责任人。既有契约例外 MUST 明确登记、限定范围并经两人评审；配置样例 MUST 只列键名，必填项使用 `KEY=` 空值形式，可选项的格式和默认值在注释或规范中说明，不得导致空值覆盖运行默认。

#### Scenario: 换无历史会话仍能读取约束
- **WHEN** 成员仅向新会话提供仓库位置及本 change 名称，要求只读说明实施计划
- **THEN** 执行者 MUST 能定位五类规范、实际代码入口、分工和任务依赖，列出对应验证命令，且不提前修改代码
- **AND** 评审记录 MUST 区分文件已存在、评审通过与实现验收完成

#### Scenario: 规范文件缺失或规则不可达
- **WHEN** 五类规范有缺失，或 `AGENTS.md` 无法指向本次修改必须读取的规范
- **THEN** 规范验收 MUST 判为未通过并指出缺失路径，MUST NOT 仅凭会话口头约定进入实现

#### Scenario: 合规改动与受控违规检查
- **WHEN** 在隔离副本中按规范实现一项本轮基线能力，再对其进行一次故意跨层或移除授权的违规修改
- **THEN** 合规版本 MUST 通过相应检查，违规版本 MUST 被自动检查或明确的人工评审规则识别并拒绝
- **AND** 记录 MUST 标明检查方式、结果和违规修改已撤去，正式产品不得保留试验性漏洞或接口

#### Scenario: 旧写法与新规范冲突
- **WHEN** 评审发现既有 HTTP/SSE、配置默认值或文件一致性处理与拟定规范不一致
- **THEN** 团队 MUST 先明确是本 change 整改还是登记兼容例外，未决冲突 MUST 阻断相关任务
- **AND** MUST NOT 为统一文字形式静默更改已验收协议或扩大本 change 业务范围

#### Scenario: 无权限或未经评审的交付
- **WHEN** 同一作者提交改动但缺少另一成员评审，或尝试绕过已配置主干保护交付
- **THEN** 团队 MUST 将该交付判为未完成，不将文档中的分工计划或作者自报通过当成评审证据
- **AND** 维护者 MUST 按真实权限结果记录，不自动修改远程保护规则来让验收通过

#### Scenario: 配置样例含取值或缺少填配置说明
- **WHEN** 配置样例有效条目包含取值，或空值可选条目覆盖运行默认且 README 没有正确填写说明
- **THEN** 样例核查 MUST 判为未通过，整理为只列键名、明确必填/可选的模板，并更新填配置指引
- **AND** 真实值 MUST 仅从私有环境注入，缺少必需配置仍必须启动失败，不得通过硬编码或回显私有 `.env` 制造可运行样例

### Requirement: 统一分模式检查入口
仓库 MUST 提供 `python scripts/check.py --mode unit|integration|api|all`，默认 `unit`。入口 MUST 复用现有测试工具并明确环境，`unit` 不启动容器或真实模型，`integration` 包含全部三个 Testcontainers 类，`api` 使用真实运行中的应用，`all` 按 unit、integration、api 依次执行。全部选定检查成功才退出 0，用例失败退出 1，参数/工具/前置环境错误退出 2；未选模式不得宣称通过。

#### Scenario: 执行正常检查
- **WHEN** 依赖已安装、所选模式环境具备，操作者从任意工作目录调用检查脚本且所有子检查成功
- **THEN** 脚本 MUST 根据自身位置定位仓库，输出选定检查的结果汇总并返回 0
- **AND** MUST 保留原 Maven/Vitest/Python 报告位置，不执行提交、推送、真实应用迁移或数据重置；测试自身在独立容器中的迁移不受此限制

#### Scenario: 模式参数非法
- **WHEN** 操作者传入未支持模式或未知参数
- **THEN** 脚本 MUST 返回 2 和用法信息，且不得运行任何测试或外部请求

#### Scenario: 工具或测试资源不存在
- **WHEN** 所选模式需要的解释器、Maven wrapper、Node 工具、测试目录或既有接口入口不存在
- **THEN** 脚本 MUST 返回 2 并仅报告缺失资源名称，MUST NOT 自动安装全局工具或输出本机私密配置

#### Scenario: Docker 或应用依赖不可达
- **WHEN** integration 无法访问 Docker，或 api 无法访问其健康入口、测试数据库或必需账号/材料
- **THEN** 脚本 MUST 返回 2，且不得把该模式转为跳过后退出 0
- **AND** MUST NOT 连接不匹配的现有数据库替代测试容器，也不得自动开启演示种子或创建真实测试前置数据

#### Scenario: 子检查失败或出现跳过用例
- **WHEN** 任一选定检查非零退出，或完整验收中出现未登记理由的跳过用例
- **THEN** 入口 MUST 返回非零并标记失败项，MUST NOT 把旧报告或未执行阶段标为本次成功
- **AND** 阻断原因解除前 MUST NOT 勾选对应验收任务或创建完成标签

### Requirement: 独立复现与可回滚交付
团队基线 MUST 由另一名成员独立克隆、按 README 填配置、一条 Compose 命令启动并通过匿名健康检查，保留既有核心业务回归。基线交付 MUST 在隔离环境验证候选与上一版本的启动及应用回滚，记录版本、成员代号、环境类别、命令、结果和耗时，证据集中保存在 `docs/lesson-07/README.md`，项目状态和归档说明只链接该总记录；MUST NOT 新建逐次验证目录、公开个人路径或原始凭据。最终交付 MUST 逐项核查仓库、规约、规范、骨架、交付五个维度，包含实际版本标签和另一成员独立启动证据。

#### Scenario: 独立启动并完成基线验收
- **WHEN** 另一名成员在独立工作副本和隔离 Compose 数据中按 README 启动候选版本，完成健康/日志验证、规定检查与回滚演练
- **THEN** 两人 MUST 能依据同一版本和脱敏记录核对结果，全部门禁通过后才能同步主规格、归档和创建基线标签
- **AND** 个人历史验收 MUST 与本次执行结果区分，未实现业务 MUST 不计入基线完成范围

#### Scenario: 缺少配置或依赖
- **WHEN** 新成员缺少必需配置，或 Docker/模型供应商等验收前置依赖不可用
- **THEN** 文档 MUST 给出具体配置项或依赖类别，相关验收 MUST 保持未完成，不得靠口头补充后仍称 README 可独立复现

#### Scenario: 角色或班级越权回归
- **WHEN** 团队基线测试中学生调用教师管理操作、班级 A 用户读取班级 B 资源，或非本人读取私人会话
- **THEN** 系统 MUST 保持当前主规格的 403/404 和数据不变保证；任一回归 MUST 阻断交付

#### Scenario: 上一版本或镜像不可用
- **WHEN** 操作者无法定位演练所需的上一版本提交/标签或无法构建其镜像
- **THEN** 回滚验收 MUST 判为未完成，记录缺失版本及处置，不得仅写出回滚命令就视为演练成功

#### Scenario: 回滚失败或目标数据不隔离
- **WHEN** 演练旧版启动失败，或其配置/数据卷可能指向现有真实应用环境
- **THEN** 团队 MUST 停止该演练并阻断回滚验收，保留失败状态且不清理真实数据
- **AND** MUST NOT 使用 `down -v`、回改已应用 Flyway 或强制覆盖历史来制造通过结果

#### Scenario: 记录含私密内容或缺少成员复现
- **WHEN** 交付记录含真实密钥、本机绝对路径、完整个人学习数据，或只有实现者本人启动记录
- **THEN** 交付 MUST 判为未完成，分别进行脱敏或另一成员实际复现后再评审
- **AND** 公开仓库和完成标签 MUST NOT 以不完整或含私密原文的记录作为验收证据

#### Scenario: 最终核查遗漏维度或标签尚未存在
- **WHEN** 团队准备宣布整课完成，但五维核查有缺失、总记录不在指定目录，或版本标签尚未实际创建
- **THEN** 团队 MUST 将整课交付保持待完成，明确缺项与后续动作；机器形式校验通过不得替代该门禁
- **AND** 仓库命名和其他实际兼容例外须明确结论；首次提交包含已有代码不得作为拒绝交付或要求重写历史的理由
