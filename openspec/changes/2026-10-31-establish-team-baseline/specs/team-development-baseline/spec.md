## Purpose

建立可持续协作的团队开发基线：规范可读取、模块责任明确、检查结果可信。按项目负责人的最新确认，本轮实现与运行验证已通过，收尾由另一成员在自己的开发环境独立启动、走通现有功能并审核，再归档提交；不追加规范破坏试验、回滚演练或全历史/镜像扫描。

## ADDED Requirements

### Requirement: 团队规范与完整模块责任
仓库 MUST 提供产品、后端、安全、测试、部署运维五类规范，明确规则、检查方法和缺陷判据；常驻规则 MUST 从 `AGENTS.md` 可达，必要技能 MUST 有输入、步骤和产出。成员 MUST 按完整功能模块或开发/测试角色负责，由另一成员评审，MUST NOT 将同一功能细碎拆成页面、接口和数据责任。配置样例 MUST 区分必填键与可选默认，不含真实秘密。

#### Scenario: 另一成员读取规则并审核
- **WHEN** 另一成员审核本轮实现、规约、规范和已有测试结果
- **THEN** 审核者 MUST 能从仓库入口定位适用规则，确认代码与约定相符，记录通过或具体问题
- **AND** MUST NOT 为完成审核额外要求无历史会话、故意破坏代码或重复全部已通过测试

#### Scenario: 规范缺失或规则不可达
- **WHEN** 必需规范缺失或 AGENTS 无法指向适用规则
- **THEN** 审核 MUST 指出缺失路径，问题修正后才能通过

#### Scenario: 兼容约定冲突
- **WHEN** 旧 HTTP/SSE、配置或一致性处理与规范冲突
- **THEN** 团队 MUST 明确整改或登记兼容例外，MUST NOT 静默改变已验收行为

#### Scenario: 配置样例泄漏或覆盖默认
- **WHEN** 样例含真实凭据，或可选空值覆盖运行默认且缺少说明
- **THEN** 审核 MUST 拒绝通过，修正样例和说明；必需配置缺失仍须启动失败

### Requirement: 统一分模式检查入口
仓库 MUST 提供 `python scripts/check.py --mode unit|integration|api|all`，默认 `unit`。入口 MUST 复用现有测试工具并明确环境，`unit` 不启动容器或真实模型，`integration` 包含全部三个 Testcontainers 类，`api` 使用真实运行中的应用，`all` 按 unit、integration、api 依次执行。全部选定检查成功才退出 0，用例失败退出 1，参数/工具/前置环境错误退出 2；未选模式不得宣称通过。

#### Scenario: 执行正常检查
- **WHEN** 依赖已安装、所选模式环境具备，操作者从任意工作目录调用检查脚本且所有子检查成功
- **THEN** 脚本 MUST 根据自身位置定位仓库，输出选定检查的结果汇总并返回 0
- **AND** MUST 保留原 Maven/Vitest/Python 报告位置，不执行提交、推送、真实应用迁移或数据重置；测试自身在独立容器中的迁移不受此限制

#### Scenario: 模式参数非法
- **WHEN** 操作者传入未支持模式或未知参数
- **THEN** 脚本 MUST 返回 2 和用法信息，且不得运行任何测试或外部请求

#### Scenario: 工具或测试资源不存在
- **WHEN** 所选模式需要的解释器、Maven wrapper、Node 工具、测试目录或既有接口入口不存在
- **THEN** 脚本 MUST 返回 2 并仅报告缺失资源名称，MUST NOT 自动安装全局工具或输出本机私密配置

#### Scenario: Docker 或应用依赖不可达
- **WHEN** integration 无法访问 Docker，或 api 无法访问其健康入口、测试数据库或必需账号/材料
- **THEN** 脚本 MUST 返回 2，且不得把该模式转为跳过后退出 0
- **AND** MUST NOT 连接不匹配的现有数据库替代测试容器，也不得自动开启演示种子或创建真实测试前置数据

#### Scenario: 子检查失败或出现跳过用例
- **WHEN** 任一选定检查非零退出，或完整验收中出现未登记理由的跳过用例
- **THEN** 入口 MUST 返回非零并标记失败项，MUST NOT 把旧报告或未执行阶段标为本次成功
- **AND** 阻断原因解除前 MUST NOT 勾选对应验收任务或创建完成标签

### Requirement: 验证通过后的成员审核与交付
本轮 MUST 保留已通过的自动检查、真实 API 和隔离运行记录。发起方已确认验证通过后，另一成员 MUST 在自己的开发环境从候选提交启动应用，实际复现现有功能，并审核代码、配置、文档、已有验证结果及本次差异中的敏感信息；复现与审核通过后由该成员记录结论、同步主规格、严格校验、归档并提交。审核未引入行为修改时 MUST NOT 默认重跑全部测试；标签按团队需要创建，不作为归档前置条件。

#### Scenario: 审核通过并交付
- **WHEN** 发起方已确认验证通过，另一成员已独立复现并审核，确认无未解决问题
- **THEN** 审核者 MUST 在 `docs/lesson-07/README.md` 记录成员代号和结论，再同步规格、校验、归档并提交
- **AND** 项目状态 MUST 更新为实际归档结果，不得由原实现者代签另一成员结论

#### Scenario: 另一成员独立复现现有功能
- **WHEN** 另一成员按 README 在自己的开发环境启动候选提交，使用自己的私有配置和合成测试数据
- **THEN** MUST 实际走通健康/日志、登录与角色/班级隔离、材料上传解析与三种检索、MCP 连接及工具审计、技能/智能体配置、持久化流式对话及页面渲染
- **AND** MUST 记录提交、成员代号、环境类别、功能结果和问题处理；不能只凭 health 200 或原作者的报告判为通过
- **AND** MUST NOT 将尚未实现的规划业务列为验收对象；已有完整自动测试可复用，不要求重新执行整套 all

#### Scenario: 复现环境或功能不可用
- **WHEN** 另一成员缺少配置、依赖不可用，或任一已实现功能无法走通
- **THEN** MUST 记录具体阻塞并保持复现未通过，修正后重试对应功能；不得直接归档

#### Scenario: 审核尚未完成
- **WHEN** 仅有发起方确认，或另一成员只看文档而未实际运行功能，或尚未提供结论
- **THEN** change MUST 保持待审核，不得将原有测试通过当成另一成员已复现

#### Scenario: 发现问题并修改
- **WHEN** 审核发现越权、契约回归、敏感信息或代码缺陷
- **THEN** 团队 MUST 修正问题并补跑受影响检查，审核者确认后再交付
- **AND** MUST NOT 删除失败断言、降低阈值或扩大权限来制造通过

#### Scenario: 证据缺失或失实
- **WHEN** 已有记录无法支持通过结论，或记录将取消的验证写成已执行
- **THEN** 审核 MUST 要求更正或补充必要证据，不得虚构结果

#### Scenario: 公开提交含敏感信息
- **WHEN** 本次差异或验收摘要含凭据、完整个人数据或私有路径
- **THEN** MUST 先移除或脱敏，MUST NOT 带问题归档提交，也不得自动重写历史
