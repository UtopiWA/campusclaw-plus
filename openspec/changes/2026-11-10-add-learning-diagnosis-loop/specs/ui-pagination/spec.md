# Frontend Pagination

## Purpose

在已授权加载的长列表上提供一致、可访问的前端分页，减少一次渲染和滚动负担，正确处理筛选、数据减少、绑定选择及会话最新消息，同时不把分页显示误当成后端完整性或授权保证。

## ADDED Requirements

### Requirement: 长列表统一分页
材料/检索、标签管理与绑定选择、作业/题库/名单、掌握度/明细、计划任务、会话列表/消息、助手/技能/MCP工具/审计及批量绑定选择 MUST 使用前端分页，默认10条并支持20/50，显示总数及有效页码；作业/题库列表、师生掌握表及已生成计划的任务列表即使不超过一页也显示分页栏；原生下拉筛选及单项有限标签不另造分页。

#### Scenario: 筛选和数据变化
- **WHEN** 筛选、切换上下文、改变页大小或删除最后一页数据
- **THEN** 页码重置或收敛到有效范围，不出现假空页；跨页复选框保留已选项，统计总数仍为完整数据

#### Scenario: 计划任务不足一页
- **WHEN** 已保存计划包含0至10项任务
- **THEN** 底部仍显示总数、每页10/20/50、1/1及禁用的前后页按钮；无已保存计划时不创建假分页或任务

### Requirement: 会话恢复最新页
会话消息 MUST 默认进入最新页，新消息追加定位末页，历史翻页不改消息、草稿或流式提交契约。

#### Scenario: 历史会话与流式追加
- **WHEN** 打开超过一页的会话或发送新问题
- **THEN** 显示最新消息，翻页可读旧消息，SSE仍仅在服务端提交后done，分页不截断持久化历史
