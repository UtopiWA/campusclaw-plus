# 团队开发与运行基线设计

## Context

动因和范围见 [proposal](proposal.md)。目前沿用 Vue/Spring Boot/MySQL/Qdrant/Python MCP 和六份主规格；当前代码具有以下约束：

- `HealthController` 只通过 `DataSource` 判断数据库，返回 `{status}`。`CampusClawIntegrationTest` 已断言匿名访问及 `status=ok`；Compose 后端健康超时为 5 秒。
- `SecurityConfig` 对 `/health` 与文档放行，对业务接口要求 Bearer；健康字段扩展不得扩大授权。
- 后端使用 Spring Boot 3.3.5，已有 Jackson/Logback，没有 JSON 日志配置、请求关联过滤器或构建版本信息。
- `AsyncConfig` 分别提供材料和会话有界执行器；会话还经过 MVC 异步分派。普通线程局部 MDC 不会自动跨这些边界。
- `GatewayRestClientFactory` 复用正常检索超时和重试，不适合作为无重试健康探测。`QdrantVectorStoreGateway.ensureCollection` 可能写入，不能用于匿名健康访问。
- README 有分散检查命令；`apitest/run_all.py` 访问实际应用并生成报告。后端有三个容器类，其中 `McpSchemaMigrationTest` 在 Docker 不可用时可自动跳过，完整门禁需额外识别此情况。
- 原主干仍为 `master`。用户已确认仓库成员/保护配置完成，本轮不调用远程修改设置；课件 `main` 的示例不要求重命名已有主干。

## Goals / Non-Goals

**Goals:** 给执行者确定的健康响应、超时、日志字段、检查模式和验收门禁；新增实现尽量复用现有技术栈；成员按完整模块负责，测试和评审可由另一成员独立完成。

**Non-Goals:** 不建立第二套认证/异常框架，不调整原有 HTTP/SSE 契约，不实现业务扩展，不增加新数据库迁移；不在当前提案阶段创建实际规范、脚本或应用类。

## Decisions

### 1. 沿用现有应用，明确规则兼容边界

后续规范阶段按五个文件组织于 `docs/standards/`：`01-product.md`、`02-backend.md`、`03-security.md`、`04-testing.md`、`05-operations.md`。每条规则写实际检查方式和不通过时的处理；`AGENTS.md` 说明按修改范围读取哪些文件，而不复制全部条文。必要流程放入仓库 `.agents/skills/`：优先复用既有 OpenSpec 技能，新增一项团队检查/交付流程即可，不为每条规则创建技能。

规范编写时必须对照以下具体内容，不以文件存在或篇幅代替合规：

| 规范 | 必须写清的条目与测评点 |
| --- | --- |
| 产品 | 用户/场景与路由；加载、正常、错误、空四状态；术语、表单校验时机、间距/字号；状态枚举/流转/允许操作；导入导出的数量/大小上限、整批校验与错误行号。未实现的导出明确不适用，不为满足规范额外开发。 |
| 后端 | 分层/依赖、接口版本、请求响应和错误码、校验位置、访问/事务、幂等及配置；非法筛选明确拒绝，排序有唯一兜底键，外部网络调用不夹在数据库事务中；继承文件补偿机制单独登记。 |
| 安全 | 默认拒绝、逐资源授权、越权用例、密钥与轮换、输入/转义、漏洞扫描频率；附件读取按业务资源授权，不新增通用文件标识读取后门；令牌存放、出站白名单及本次差异和公开记录的敏感信息检查。 |
| 测试 | 正常/失败/边界、分层来源、数据隔离、统一入口及失败阻断；明确本项目采用 HTTP 状态和响应/数据变化判定，区分被当成成功、被放行、被误拒、未处理故障；每个测评点都有操作及缺陷判据。 |
| 运维 | 可复现构建、环境配置、健康与优雅停机、JSON/request ID 字段、发布回滚、迁移顺序、备份恢复目标；本轮复用已通过的运行记录，由另一成员审核。 |

AI、数据与评审补充要求纳入相关规范：工具经已有服务层、提示词随版本且有标识、输出校验/不编造依据；按已有能力准备 10～20 条含拒答的评测样本；迁移纪律、敏感分级、留存及删除时的业务库/向量/文件/备份副本；完成定义、变更规模上限、评审表和例外书面化。不把补充类别自动扩大为本轮新业务或八份独立文件。

课程对配置样例要求只写键名，当前 `.env.example` 的安全占位值和非敏感默认值仍需整理：实施时提供 `KEY=` 的空值条目，格式、必填/可选和安全默认值写在注释或运维规范，真实值只由成员私有 `.env` 注入。可选默认项不传空字符串覆盖运行默认；模板区分必填空值条目与注释中的可选键名。此调整不意味着删除应用既有安全默认值；复制模板后仍需先填配置才能启动，README 要同步写清。

继承项目保留已有代码和提交历史，首次团队提交允许包含代码，不设“首次只能提交三个文件”的门禁，也不要求为此补充例外审批或修改历史。仓库短名、主干保护、忽略规则和秘密历史检查仍按实际证据核对。

明确登记以下继承约定：已有 `/api/**`、成功 DTO/`{error}` 和 SSE 不批量改为新前缀或统一外壳；文件隔离与事务补偿不按“事务内绝无文件操作”的示例机械删除；非敏感超时/阈值允许已有安全默认值，秘密和必需地址缺失仍失败；纯工具依据可支持无材料 citations 的生成。AI、数据和评审约束放入相关五类规范，不另建八份重复文件。

备选是按新项目模板重建目录、协议和全部配置，收益不足以抵消继承功能回归与迁移风险。范围文档按整体模块重新分工，个人信息保持不变。

### 2. 健康响应扩展与就绪范围

保留 `/health`，响应示例：

```json
{"status":"ok","version":"0.1.0","time":"2026-10-31T00:00:00Z","dependencies":{"database":"up","qdrant":"up","chat":"not_checked","embedding":"not_checked","mcp":"not_checked"}}
```

`version` 默认来自 Maven 生成的 `build-info.properties`；未打包开发运行需执行相应资源生成。允许非敏感 `APP_VERSION` 作为部署标识覆盖，按 specs 的 1～64 字符规则校验，显式空值视为非法。构建/运行不得读取远程 Git、本机用户名或工作区路径。发布和回滚分别提供对应标识，以便在隔离演练中核对。

Controller 只组装响应；新增小型健康服务组织固定的两个只读探测：数据库从既有池获取连接后 `isValid(1)`，Qdrant 仅访问 `/readyz`。数据库连接池获取超时保留当前 3000ms；Qdrant 使用独立的 1000ms 连接和 1000ms 读取超时，不调用正常业务重试或集合管理。顺序执行的受控故障上限约 6 秒，HTTP 验收给出 8 秒界限，Compose 后端探测超时调整为 10 秒，其余健康重试和启动时限不扩大。测试必须证明失败不挂起以及恢复后重新成功。

数据库与向量服务是当前检索基线的固定就绪依赖；Chat/Embedding 缺乏通用、免费且无副作用的探测协议，MCP 服务又是按班级动态配置，均显式标记 `not_checked`。HTTP 200 只表示数据库/向量依赖就绪，不能宣传为全部 AI 能力可用。API 回归与真实模型验收继续独立证明这些能力。该边界在运维规范和 README 简述，避免匿名探测发生成本或遍历班级配置。

备选是加入 Actuator 或对所有供应商执行生成/工具调用：前者超出本次最小基线，后者有副作用、费用和权限问题。此轮不拆存活/就绪两个端点，后续需求明确时另建 change。

### 3. 后端日志与异步生命周期

利用现有 Logback 和 Jackson 输出 JSON，不因格式化引入新日志框架。采用小型编码器及固定结构的请求完成事件，启动横幅关闭，多行异常不直接输出。稳定字段为 `timestamp/level/logger/event/requestId`；完成事件增加 `method/path/status/durationMs`。业务失败只记录稳定失败代码或异常类别，禁止拼接异常原文；框架请求体、SQL 参数、网关正文等调试输出保持关闭，必要的库日志也必须经同一编码与脱敏处理。

在 Security 之前设置过滤器，先校验或生成请求 ID、回写 `X-Request-Id`，因此 401/403/404 也可关联。仅单一合法头值可沿用；多值、非法、空或过长输入生成新 UUID。请求完成事件只使用无查询字符串的路径，不记录头、参数与正文。

请求结束不得仅依靠初始 Servlet 分派的 `finally`：异步响应使用请求属性保存状态、监听完成/错误/超时并用一次性标识避免重复完成日志。每次分派进入/退出时保存恢复 MDC；两个既有执行器加上下文复制/恢复装饰器，涵盖上传派生任务和 SSE。无请求恢复调度不继承其他用户 ID。既有业务正文、流式事件和提交时序保持不变。

备选仅使用控制器日志或 ThreadLocal：会漏掉安全过滤链拒绝、异步错误和线程复用污染，不能满足验收。

### 4. 单入口按环境分模式，而不是宣称全部离线

新增 Python 标准库脚本 `scripts/check.py`，通过参数列表调用现有工具，不拼接 shell 字符串；根据脚本位置定位仓库，跨 Windows/Linux 选择 `npm.cmd`/`npm` 与相应 Maven wrapper。使用已安装依赖，不自动安装全局工具、修改 `.env` 或启用种子。

| 模式 | 执行内容 | 前置条件 |
| --- | --- | --- |
| `unit`（默认） | OpenSpec 严格校验、前端 Vitest/构建、后端非容器套件、`python -m unittest discover -s mcp-server/tests`、检查脚本自身测试 | 已安装前后端依赖和工具；运行期不使用 Docker/真实模型 |
| `integration` | `CampusClawIntegrationTest,QdrantIntegrationTest,McpSchemaMigrationTest`，读取本轮 Surefire 计数检查是否跳过 | Docker 可访问；不使用现有应用数据库替代独立容器 |
| `api` | 复用 `apitest/run_all.py`，保留清理与报告语义 | 真实应用/数据库/MCP/模型可用、已有账号和 READY 材料，Python 依赖已安装 |
| `all` | 按上述三组顺序执行，遇到失败停止后续组并汇总已执行/未执行状态 | 三组条件均满足 |

unit 明确排除三个容器类，属于选定检查范围，不是假装集成用例通过；integration 不排除其中任何一类，Docker 缺失与跳过不得变为绿色。依赖下载属于安装阶段，不承诺尚未安装的项目断网即可检查。

子进程输出不读取或回显 `.env`；汇总仅保存模式、检查名、耗时、退出码和报告相对位置，避免复制含请求的原始日志。若确需解决测试客户端与 Docker API 兼容，允许测试专用环境项 `TESTCONTAINERS_API_VERSION`，仅接受 `1.` 加 1～2 位数字，并转换为 Maven `-Dapi.version=...`；非法值退出 2，缺省不覆盖客户端。该项不写入应用运行配置，不携带本机版本记录。

脚本退出值：成功 0、测试/规约失败 1、工具/参数/前置环境问题 2；既有接口脚本的 1/2 语义保持。受环境影响的失败保持失败；完整交付还需人工/成员门禁，脚本成功不自动归档、提交或打标签。

### 5. 完整模块负责，另一成员审核

| 模块 | 主责 | 交叉责任 |
| --- | --- | --- |
| 运行基线：健康服务、版本、JSON 日志、请求上下文、相关测试与运行配置 | 成员 A | 成员 B 审核实现与已有验证结果 |
| 工程检查与交付：统一入口、脚本测试及交付记录 | 成员 B | 成员 A 审核检查结果 |
| 规约、五类规范、兼容例外与最终验收 | 两人共同确认 | 每个模块主责维护其完整说明，另一成员评审，不按前后端分割 |

未来业务按两个较大领域划分：成员 A 负责学习证据与知识诊断（题库、作业、提交、判题、错题、知识点关系及掌握度）；成员 B 负责个性化辅导与教学分析（计划、推荐练习、角色协作、班级统计及建议）。每人对所属模块的数据、接口、页面、测试和说明整体负责；共享契约先评审，不同时拆改同一功能。

### 6. 另一成员独立复现、审核并提交

项目负责人已确认本轮验证通过。另一成员先在自己的开发环境按 README 启动候选提交，使用自己的配置和合成数据走通现有功能，再审核实现、规约/规范、配置说明、已有结果和本次差异中的敏感信息；有问题则修正并补跑受影响检查，独立功能复现必须执行，但无修改不重复整套自动测试。审核结论继续记入 `docs/lesson-07/README.md`，项目状态只保留摘要和链接。

审核通过后由该成员同步主规格、执行严格校验和差异检查、归档并提交。标签按团队需要，不作为归档前置条件。无历史会话、合规/违规实验、回滚演练和全历史/镜像扫描已移出本轮完成门槛，不将取消项记作通过；运维流程保留为后续按需参考。

## 能力—场景—验证对应

| 能力/要求 | 场景范围 | 实现阶段验证 |
| --- | --- | --- |
| C1 `auth-upload` 健康检查 | 正常、数据库故障、Qdrant 故障、8 秒超时、非法版本、越权兼容、参数无副作用、配置缺失 | 新健康服务/Controller 聚焦测试、既有 Security/集成测试、Compose 故障与恢复演示 |
| C2 `request-observability` | 请求头边界、401/403/404、依赖失败、SSE、后台线程复用、敏感标记与换行 | 过滤器/编码器/异步测试、真实请求 JSON 行核对与 SSE 回归 |
| C3 `team-development-baseline` 规范 | 规则可达、文件缺失、未评审、兼容冲突、配置样例 | 文件与链接检查、另一成员审核 |
| 同上：统一检查 | 正常、非法模式、资源缺失、Docker/应用不可达、非零退出与跳过 | 脚本标准库单元测试、四模式实际结果与新旧报告区分 |
| 同上：复现与审核交付 | 独立启动与功能复现、环境/功能不可用、审核未完成、敏感差异 | 另一成员按课程记录中的待办操作，记录功能结果，再审核、同步规格、校验、归档提交 |

每个 capability 均覆盖至少四条失败路径。健康接口为固定匿名单资源，不虚构“跨班健康资源”；其权限由后续业务请求验证，资源不存在类由观察 404 场景覆盖。工程检查没有学生/教师 API，权限失败对应主干评审门禁，资源不存在对应必需文件缺失，外部失败对应 Docker/应用不可达。

## 最终审核要点

另一成员一次性核对：实现符合规约、五类规范及入口完整、已有测试和运行结果可信、配置与文档一致、本次差异无敏感信息。另一成员还须实际复现全部现有功能并记录通过或待修正；具体操作集中在课程记录中，不追加其他实验。

## Risks / Trade-offs

- 就绪口径比原版严格：数据库正常但 Qdrant 故障会从 200 变 503 → 明确这是本次有意变更；探测只读、无重试，Compose 超时同步调整为 10 秒。
- `not_checked` 可能被误读为全部依赖正常 → JSON 显式保留这些值，README/规范说明只证明固定依赖，真实接口验收另跑。
- MDC 与流式完成容易漏清理 → 覆盖重复分派、客户端断开、失败/超时与线程复用，避免事件重复和身份混淆。
- 第三方日志可能含敏感内容 → 关闭正文/SQL 参数调试，统一 JSON 编码并用敏感标记做负向验证，不复制原始日志到公开文档。
- 另一成员审核仍需实际结论 → 保持审核任务待完成，代理不能根据自身测试代签。

## Migration Plan

实现与验证已完成、发起方确认通过 → 另一成员独立启动、功能复现并审核 → 必要修正及受影响检查 → 记录结论 → 由审核成员同步规格、校验、归档并提交。

本轮无业务数据迁移。新增健康字段与请求响应头对现有客户端为增量兼容；HTTP 503 的更严格就绪范围、JSON 日志格式及 Compose 健康超时是明确的运行变化。回滚恢复前一版应用与配置，不回改已有迁移或删除数据。
