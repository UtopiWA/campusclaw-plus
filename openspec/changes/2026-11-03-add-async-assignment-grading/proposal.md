# 增加可靠异步作业批改与 AI 审核基线

## Why

第 8 课要求把耗时批改变成可查询、可恢复、可去重的后台任务，并把“AI 生成 → 自审 → 同伴评审 → 检查通过 → 合入主干”落实为有记录的团队流程。当前仓库只有 `assignments` 的 ID、班级、标题骨架，没有提交、评分和结果链路；材料解析虽然已有数据库状态、原子认领和恢复调度，但使用进程内线程池，不是独立消息代理与消费者。

本 change 实现“教师提供任务和评分依据 → 本班学生提交 → 后台 AI 辅助批改 → 教师终评”。2026-11-04 用户已明确授权验收反馈修正：全站顶部自动消失消息、作业页统一视觉、文件评分依据、每人每作业仅提交一次及教师终评，实施无需另等确认。完整题库、知识图谱、学习计划和班级分析仍不在本次范围。

本 change 交付设计、实现和验收证据。设计阶段先评审再实施；当前实际结果及待确认项见 `docs/lesson-08/`，只提交设计文档不满足完成标准。

## What Changes

- 2026-11-06 用户授权补齐安全自查及相关文档，新增可重复检查入口和 reports/ 六份报告；本轮不修复自查发现的业务基线缺口，不执行选做的提示词注入试验。另一成员复现暂缓，完成其余任务后统一交付，由对方验收后办理最终提交。
- 用户进一步决定将技能 ID 和 Token 用量暂时搁置，不列入本次同伴复核、修复任务或归档前置条件；保留原始 SEC-07 记录，不将缺口写为已修复。另一成员仍需完成实际功能复现、至少两项授权安全检查及代码评审。
- 首次 Docker 复现使用模板中显式的团队数据库和宿主端口，避免自查误用旧默认值；交接补齐安装、私有配置、种子停用、Python 隔离环境和验收清理。只更新新配置模板，不修改已有私有配置或 Compose 的兼容默认值。
- Python 验收启用 PyMySQL 官方 RSA extra，覆盖 MySQL 8 完整认证路径，不依赖已有认证缓存；仅影响验收工具依赖，不修改数据库认证方式。

- 新增能力 `assignment-grading`：教师在本班创建带评分依据的文本作答任务；学生提交文本作答；系统异步生成有依据的 AI 综合分数与评语；学生/教师按权限查询任务与结果。
- 新增能力 `reliable-task-execution`：引入独立消息代理（RabbitMQ）、事务性发件箱、独立可启停消费者、至少一次投递、结果唯一约束、有限重试、指数退避与抖动、死信和任务关联观测。
- 新增 Flyway V8 迁移：扩展 `assignments`，新增 `submissions`、`grading_tasks`、`grading_results`、`grading_outbox`；只增不改已交付迁移。
- Compose 新增 RabbitMQ 服务与独立 `grading-worker` 服务；配置、健康检查、持久化卷和 `.env.example` 同步更新。
- 前端新增 `/assignments`：教师创建任务、查看本班提交与结果；学生提交文本并轮询任务状态。
- 新增测试、接口用例和批量扫描入口；更新审核规则，新增课程验收与评审记录文档。
- 评分口径（2026-11-05 用户明确授权调整）：模型结合题目、总分、参考答案与学生作答综合给出整数分数和有依据的评语；不提取或硬套文件评分项，不做满/半/零规则计分。服务端严格校验结构、类型、范围和解释，教师仍可独立终评。
- 教师创建弹窗输入标题、详细题目、总分，选择本班已解析的参考答案文件；保存参考答案原文快照，创建时不调用模型；模型只在后台批改时调用。保留旧结构化创建 API 兼容，但新页面使用文件绑定。
- 学生每人每作业只能提交一次；相同请求保持幂等，不同内容再次提交返回 409。内部历史版本字段保留兼容，不向页面展示。
- 教师通过改分弹窗查看作答、AI 分数/评语/依据，填写终评分数和评语；终评独立存储且优先展示，AI 原始结果不覆盖。
- 成功/失败操作提示全站统一为顶部自动消失消息；重做作业页，复用已有应用壳、弹窗与设计令牌，移除英语装饰和内部任务信息。
- 仅在团队环境清理用户指定的两个合成 MCP 及可确认的示例作业/批改数据，不操作其他项目和用户正常数据。
- 版本标签：按本次迭代说明命名，验收后按团队授权创建；Class07 的“标签非默认门槛”约定不自动沿用，本 change 单独要求标签交付。
- 工作拆分：成员 B 负责 change/规则/验收/扫描/交叉评审；成员 A 负责异步批改的完整实现。两人都要实际读代码，代理不能代签结论。

## Capabilities

### New Capabilities

- `security-precheck`：SEC-01～07自查、历史/产物/日志密钥检查、依赖基线及六份报告；同伴复现单独记录。

- `assignment-grading`：作业创建、学生文本提交、任务状态与结果查询、权限和可解释评分边界。
- `reliable-task-execution`：消息代理、事务性发件箱、独立消费者、至少一次投递、幂等、重试/退避/死信和观测。

### Modified Capabilities

无。现有登录、材料、检索、会话和 MCP 契约保持不变；本 change 不修改主规格，归档时再同步新增能力。

## Impact

- 后端：新增作业/提交/任务/结果/发件箱实体与仓储、RabbitMQ 配置、发件箱投递器、`grading-worker` 消费者、模型辅助评分适配器、任务查询与作业接口；复用现有鉴权、班级隔离、模型网关、Flyway 和检查入口。
- 前端：新增作业路由、教师创建/查看页面、学生提交与状态轮询；复用现有应用壳、表单和错误反馈约定。
- 运行：Compose 新增 RabbitMQ 与 worker；新增数据库迁移、环境变量和健康检查；worker 可独立停止/启动，Web 与查询接口保持可用。
- 测试：新增后端单元/集成、前端交互和接口用例；新增三条核心判据、故障/并发验收和批量扫描证据；原有 `check.py` 三模式需扩展或新增固定扫描入口。
- 文档：更新 `AGENTS.md`、`docs/standards/04-testing.md`，新增 `docs/lesson-08/README.md` 与 `review.md`；实现完成后同步 README、项目状态和配置说明。
- 兼容：不改既有 HTTP/JSON 与 SSE 契约；不修改旧迁移；旧应用在新迁移后可继续运行，新应用回滚到旧版本时保留新增表和消息代理卷。

## Non-goals

- 不实现作业/评分依据编辑、原版本重新批改或学生二次提交；历史版本数据保留，但新写入遵循一次提交规则。
- 不实现完整题库、题型系统、知识图谱、掌握度、学习计划、班级共性错误分析。
- 不承诺端到端 exactly-once、SSE/WebSocket 任务推送、全功能任务调度平台或全站异步。
- 不把材料解析改造成本课的验收对象；材料异步现状只作为工程背景。
- 不修改现有登录、材料、检索、会话、MCP 和 SSE 行为；不把模型分数当作不可解释的最终事实。
- 不提交真实学生作答、模型密钥或完整敏感日志。
