# 后端与数据规范

适用于 Java/Python 服务、接口、数据模型和业务状态。先读对应 change 与 [安全规范](03-security.md)；不得在未评审的范围外新增接口或迁移。一个完整模块由一名成员负责，另一名成员评审验证，不按 Controller/Service/页面拆分责任。

## 1. 分层和接口约定

| 规则 | 本项目落点 | 检查与违规处置 |
| --- | --- | --- |
| 请求层只接收/校验/映射输入输出 | `auth/material/retrieval/agent/conversation/mcp` 下 Controller；业务进入 Service | 评审 Controller 是否直接写库、操作文件或请求模型；新增反向依赖阻断合并 |
| 业务层组织授权、状态和事务 | Service 调用 `persistence` 仓储及 `gateway`/MCP 适配器 | Repository 不依赖 Controller，网关不依赖 HTTP 视图；违规先修代码或登记有范围的继承例外 |
| 当前身份由服务端确定 | `CurrentUserService` 回查角色/班级/启用；组合条件查资源 | 客户端 `classId/userId` 不扩大权限；对照拒绝测试和数据不变断言 |
| 外部调用集中在适配层 | `GatewayRestClientFactory`、`McpHttpClient` | 不在 Controller 拼 HTTP，不在数据库长事务中等待模型/MCP |
| 接口保持现有风格 | `/api/**`、小写资源路径、camelCase DTO、JSON；SSE 单独契约 | 不批量改 `/api/v1` 或统一业务码外壳；兼容变化先更新 specs |

新输入用 Bean Validation 与业务校验分工：格式/长度在边界，归属、状态及唯一性在 Service，数据库约束兜底。非法筛选枚举/范围须明确 400，不能忽略条件返回全量；未知业务身份字段按已有拒绝/忽略契约处理，不将其当筛选。现有不支持筛选的列表不因此被授权新增筛选 API。

## 2. 成功、失败和流式契约

成功使用已有 DTO 或规定的空响应；已映射业务错误为 `{error: 可公开信息}`。HTTP 是成败与类别的主要信号，不引入另一套独立业务码。框架级校验/反序列化错误也须在受影响接口测试中明确，不能假定未覆盖的异常已有相同外壳。

| HTTP | 适用情况 | 验收要点 |
| --- | --- | --- |
| 200/201/204 | 查询/正常操作、创建、规定的无正文成功 | 依具体接口检查字段与数据库变化，不只断言 2xx |
| 400/413 | 参数不合法/上传过大 | 不产生半成品记录，不回显秘密 |
| 401/403 | 未认证/当前角色无权限 | 不泄露正文，不因前端隐藏控件就省略测试 |
| 404 | 不存在、跨班或非本人资源 | 保持同形，不能另回“存在但无权” |
| 409 | 状态/唯一性冲突、有历史不能删除 | 原配置/数据保持一致，不乐观显示已删 |
| 502/503 | MCP 协议/上游错误、依赖或资源暂不可用 | 使用既有稳定错误，不输出供应商原文 |
| 500 | 已映射的文件操作等内部故障 | 脱敏并核对事务/补偿状态 |

会话仍用 `meta → delta* → done`，失败用既有 `error`；`done` 仅在助手消息提交后发送，流开始前错误仍走普通 HTTP。新增请求 ID 是响应头，不塞进业务 DTO 或增加 SSE 调试事件。纯工具回答允许空 citations，材料和工具都无可靠依据才在生成前固定拒答。

## 3. 事务、幂等、并发和排序

- 数据库事务保持短小；外部网络在事务外，回写前校验当前配置版本。MCP 连接采用快照/外部探测/短事务替换缓存，不自动重试。
- 材料上传、删除的文件隔离和事务同步补偿是继承机制，允许有限文件操作；必须保持主事务失败清理孤立文件、上传后解析失败保留原文件。不能套用“事务内不做网络”而删除此机制。
- 后台材料以条件更新认领，线程队列不是状态真相源；删除向量的持久化清理 job 继续补偿。不能用“重试一下”替代记录失败阶段。
- 新增写接口必须声明重复请求语义：无副作用读取、幂等更新或有明确冲突/去重机制。未来作答提交、教师复核与计划调整须先规定幂等键/并发冲突；当前会话发送不宣称通用幂等，前端禁重复点击不能代替服务端保证。
- 新增或修改排序必须有唯一兜底键，例如 `created_at DESC, id DESC`，相同时间结果可复现。材料/会话旧列表目前只有时间排序，登记为继承例外，不虚称已符合；本轮不顺带修改未触及的业务排序，下一次改动相应列表时补齐并测试。

**检查与处置：** 重复提交、并发状态变化和外部失败要同时断言 HTTP/消息状态与数据数量；任何半提交、重复业务事实或丢失归属均阻断该模块交付。

## 4. 配置与数据字典

秘密和必需地址仅从服务端环境注入，必需缺失应失败；可选非敏感默认值集中在配置，不在业务逻辑散落读取环境。`.env.example` 的只列键名目标与现有差异见 [运维规范](05-operations.md)，本规范不直接修改运行配置。

| 数据范围 | 关键事实与归属 | 维护约束 |
| --- | --- | --- |
| `classes/users` | 用户关联当前班级，BCrypt 密码哈希、角色及 enabled | 不把 JWT 签发时身份当永久权限 |
| `materials/knowledge_entries/knowledge_chunks` | class/material/entry/chunk 追溯关系；原文件、正文、切片分层 | offsets 与 Unicode code points 契约不变 |
| Qdrant points | 纯编号 payload，与 MySQL chunk ID 对应 | 不保存正文；班级过滤并回表验证 READY |
| `assistants/skills` 及绑定 | 本班配置、技能原文与有序 tool_refs | 替换绑定需原子；服务改名不静默改写原文 |
| `conversations/messages` | 本人+本班会话，正文/引用/工具快照 | 非本人不可读；FAILED 不进入后续模型历史 |
| `mcp_servers/mcp_tools/mcp_tool_calls` | 班级服务、发现缓存、调用归属及脱敏审计 | `v1:` 加密凭据；有审计服务不可硬删；耗时可空不伪造 |
| `vector_cleanup_jobs` | 持久化补偿信息 | 外部清理失败不能让已提交事实丢失 |
| `assignments/submissions/grading_tasks/grading_results/grading_outbox/submission_reviews` | 本班作业及文件快照、本人一次作答、兼容历史版本、任务/AI 结果、独立教师终评与事务性发件箱 | 实际文本异步批改见 Class08；短事务、唯一结果、attempt 隔离和恢复不得省略 |

新表/字段使用既有 snake_case，Java/JSON 使用 camelCase；状态和归属、唯一键、查询索引、时间含义写进 change。服务端时间用 UTC，新增持久化业务至少声明创建/更新或不可变事件时间及操作者来源。不是每张历史表都已有完整审计字段，不做无规约的补列。

Flyway 已交付迁移只增不改（当前应用含 V9）。新迁移必须在空库和上一版本库验证，说明前向兼容、幂等需求与数据恢复；应用回滚不等于执行反向 DDL，禁止靠修改已应用迁移或 `clean` 绕过校验。新业务数据的分级/留存/副本删除规则同时评审，具体保留策略见安全与运维规范。

## 5. AI 与工具服务边界

作业评分允许模型参考答案综合给分，必须保存解释、校验 JSON 类型/分数范围且支持教师终评；不得以格式合法冒称评分语义一定正确。掌握度、统计和推荐约束仍由明确算法决定，未实现的业务不视为已有能力。当前模型不自主选工具或构造参数，工具经已有服务层和显式适配器执行；新增适配器需要 schema、权限、边界及失败场景。

提示词及技能模板随代码/迁移入库。作业批改结果已有 promptVersion（当前默认 v4）；创建时只保存参考答案快照，不调用评分项提取模型。会话历史来源由提交与技能原文追溯；下一次修改提示词模板必须有显式版本标识及评测变化记录，不为此修改现有业务表。模型输出先校验引用/结构/状态，再交付，拒绝或解析失败不替换为看似成功的默认成绩/计划。

材料采信沿用宽召回 0.35、双路 0.45、强向量 0.55；RRF 不是置信度，不能为通过演示调低阈值。模型正文/供应商异常和 MCP 原始结果不得进入日志；超时、结果限长及注入过滤沿用主规格。安全细节由 [安全规范](03-security.md) 定义，固定评测样本由 [测试规范](04-testing.md) 维护。
