# 产品与前端规范

适用于页面、交互和展示文案。已实现行为以 [主规格](../../openspec/specs/) 为准，功能分工见 [项目范围](../project-scope.md)；本规范不授权新增业务。新规则约束后续改动，历史差异按本文登记，不把规范已编写视为页面已通过验收。

## 1. 用户、场景与入口

| 路由 | 用户与任务 | 当前约定 |
| --- | --- | --- |
| `/login` | 教师/学生登录 | 成功后进入材料页；失败保留账号，不回显密码或内部错误 |
| `/materials` | 师生查阅/检索本班讲义；教师管理材料 | 同页管理与直接检索，不另建临时聊天页 |
| `/assistants` | 教师配置技能、智能体及 MCP | 学生路由保护；后端仍独立授权 |
| `/conversations/:id?` | 师生使用本人助手会话 | 列表、正文、底部输入器；历史恢复以服务端为准 |
| `/assignments` | 教师创建作业/查看本班提交；学生提交和查询本人结果 | 202 后显示真实任务状态；轮询至终态，刷新恢复，模型辅助结果不标为教师已复核 |
| `/`、`/search`、未知页面路径 | 兼容导航 | 当前均跳转 `/materials`；业务 API 的 404 不改成页面重定向 |

新增入口必须在相应 change 定义服务角色、触发操作和正常/失败结果，并更新本表；“作业”“学情”等尚未实现入口只能显示待建设，不能显示伪造统计或可点击的空链接。同一功能保留一个主入口。

**检查与处置：** 对照 `frontend/src/router/index.js` 和 `AppShell.vue` 逐页访问；出现无规约路由、学生管理控件、孤立入口或虚假完成状态，阻断该模块验收，由整体负责人修正，另一成员复查。

## 2. 四状态和表单

| 状态 | 页面必须让用户看到什么 | 检查与缺陷判据 |
| --- | --- | --- |
| 加载 | 明确“加载中/处理中”；写操作禁用重复提交，输入器状态可辨 | 用延迟替身观察；无限占位或能重复创建记录不通过 |
| 正常 | 实际结果、可执行操作和当前身份范围 | 对照响应与持久化结果；不得只因按钮点击就显示成功 |
| 错误 | 发生了什么、可公开原因、下一步动作 | 模拟拒绝/断网；不得显示空结果冒充错误，或暴露堆栈/地址 |
| 空 | “暂无材料/会话”或“未找到相关内容”，给可行下一步 | 空集合仍能导航/重试；纯白区域或伪造一条结果不通过 |

必填控件有可见标签；输入边界在提交前校验，已出错字段在修改/失焦时更新提示。错误紧贴字段；请求错误放当前弹窗或当前轮，不盖在另一页面。提交期间禁止重复触发，失败保留可修正输入；后端幂等不能靠按钮禁用代替。删除等不可逆用户操作应明确对象并确认，不能把服务端失败乐观显示为成功。

材料上传只表示 `PENDING/QUEUED` 已提交；解析与索引可能失败，不能立即显示“可检索”。会话切换/删除清除草稿，进入历史会话定位末尾；引用摘录默认折叠。错误后重试要使用原问题或保留查询输入。

## 3. 状态枚举和允许操作

| 对象 | 状态/流转 | 允许操作与边界 |
| --- | --- | --- |
| 材料 | `QUEUED → PARSING → INDEXING → READY`，失败进入 `FAILED`；数据库状态另有 `PENDING/INDEXING/READY/FAILED` | 展示阶段与失败代码；仅可重试失败开放重新处理；重建只改 chunks，不重新解析原文件 |
| MCP 服务 | 未连接 → 连接发现成功；失败/断开清空工具缓存 | 教师管理；有审计不可硬删，提示断开；保存配置不等于连接成功 |
| 会话轮次 | 用户已提交 → 流式输出 → `COMPLETED` 或 `FAILED` | `done` 后重载最终正文；中途失败保留已有内容，不把局部工具失败当整轮失败 |
| 技能/智能体 | 启用/停用 | 有真实消息历史的智能体停用而非强制删除；学生不编辑配置 |

新业务必须在其 change 中列枚举、允许转移、终态和重复操作语义；未授权转移须有失败场景。检查页面按钮与服务端状态逐项一致，不另建前端专属的“成功”真相源。

## 4. 导入、文件和边界

- 材料支持 `.txt/.md`，UTF-8、非空，当前默认上限 2 MiB，由 `MAX_UPLOAD_BYTES` 决定。前端文案目前固定 2 MiB，属于继承差异；部署变更上限时必须一并审查提示，不声称已动态同步。
- 技能导入当前是单文件文本，不是 ZIP 或批量导入：来源最多 8000 Unicode code points，名称 32、条件 120、资料范围 32、说明 2000；UTF-8 解码和元数据完整校验后才保存，失败不覆盖数据库配置。
- 当前技能导入错误不提供完整逐行诊断。新批量导入能力须先定记录数/字节上限、整批验证与原子提交、1 起始错误行号和错误明细；超限或任一无效行不得部分入库。它不属于本轮基线实现。
- 当前没有通用导出，注明不适用，不为“规范齐全”添加导出按钮。新增导出须在 change 指定范围、权限、条数上限与敏感字段排除。

**检查与处置：** 使用空文件、无效 UTF-8、超过上限和重复字段分别操作，核对错误与配置未覆盖；客户端校验通过不能替代服务端验证。超长输入测试按 code point 计算，不用 UTF-16 长度冒充。

## 5. 文案、视觉和可达性

统一术语：材料页叫“讲义与检索”，配置页叫“助手配置”，会话页叫“助手对话”；后台“材料”“知识条目”“检索切片”是不同层次。MCP 工具展示中文名并保留英文工具标识；没有真实 Token 用量不估算，没有真实执行阶段不虚构“AI 思考”。

新增页面复用 `AppShell`、`BaseModal`、`AppIcon` 和 `frontend/src/styles.css`；主色使用 `--brand-700`，状态色使用 `--success/--warning/--danger`，圆角 8/12/16，新增间距优先 4/8/12/16/24/32px。标题、正文、辅助文字建议 24/16/14px，特殊紧凑元素可沿用既有层级；不把新令牌建议当成全站样式重构任务。

至少核对 1440、1000、760、470、375px 视口：桌面侧栏、中宽收缩、手机抽屉与底部输入均可用，无主操作横向溢出。主链可用 Tab/Enter/Escape，输入与标签关联，图标按钮有可访问名称，错误有警报语义，普通正文对比度目标 4.5:1，不仅靠颜色传状态。`BaseModal` 已有初始焦点和 Escape，但不能据此宣称已验证完整焦点圈定；新改弹窗须实际检查焦点进入、退出与返回。

**检查与处置：** Vitest 覆盖交互与错误态；真实浏览器检查上述断点和键盘主链。模拟 API 只能证明展示逻辑，不能证明真实接口/权限。新增自造主题、缺标签或主操作不可达，由该模块负责人修正后交叉复查。
