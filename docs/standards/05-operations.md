# 部署、配置与运维规范

本规范记录部署约定、继承例外和后续目标。健康字段、JSON/request ID、构建版本和统一检查已加入实现；自动检查与真实部署验收分别记录，不因代码存在就视为交付完成。

## 1. 构建、环境和配置

后端 Maven/JDK 17、前端 Node 22 构建及锁文件、Python MCP Dockerfile 和 Compose 一同维护；使用仓库 wrapper 与锁文件，不用成员本机全局版本作为唯一前提。镜像/交付记录关联候选提交；发布只改部署配置，不在容器内手改源码。既有基础镜像按版本标签固定、未全部锁 digest，这是继承边界，不能宣称位级可重现；如需升级或锁定，单独评审。

本地、测试和公开演示分别使用私有 `.env`、独立数据库/卷及凭据；真实模型验收说明环境类别，不公开供应商密钥或本机地址。当前不实现生产级高可用、蓝绿发布或多租户。

配置样例**只列键名**：必填条目 `KEY=`，可选项以注释列键名并写格式/安全默认。覆盖可选项时写成 `KEY=值`，避免空值覆盖默认。已有私有 `.env` 不随模板自动改写。

| 配置组 | 项目键名及判据 |
| --- | --- |
| 数据库 | `MYSQL_ROOT_PASSWORD/MYSQL_PASSWORD` 为私有非空值；Compose 的库名/用户默认 `campusclaw`，`MYSQL_HOST_PORT` 默认 3306；后端独立运行用 `DB_URL/DB_USERNAME/DB_PASSWORD` |
| 认证/种子 | `AUTH_JWT_SECRET` 至少 32 UTF-8 字节，`AUTH_JWT_TTL` 默认 PT8H；`DEMO_SEED_ENABLED` 默认 false，仅开启时要求 `DEMO_SEED_PASSWORD` |
| 模型 | `EMBEDDING_BASE_URL/API_KEY/MODEL/DIMENSION` 与 `CHAT_BASE_URL/API_KEY/MODEL` 必须按实际服务填写；维度匹配 Cosine collection；`CHAT_REASONING_EFFORT` 默认 none，显式空值用于省略该供应商扩展字段 |
| MCP | `MCP_AUTH_TOKEN` 与登记服务的 Token 一致；`MCP_TOKEN_ENCRYPTION_KEY` 是独立 32 随机字节的 Base64；白名单默认 mcp-demo；连接/读取默认 3s/10s |
| 材料/检索 | `MAX_UPLOAD_BYTES` 默认 2097152；连接/读取 3s/30s；宽召回/双路/强向量为 0.35/0.45/0.55，必须有序，RRF K=60 |
| 基线版本 | `APP_VERSION` 可覆盖 Maven build-info 的项目版本，匹配 `[A-Za-z0-9][A-Za-z0-9._-]{0,63}`；显式空值/非法值拒绝，不读取本机 Git 路径或远端作为运行依赖 |
| 测试专用 | `TESTCONTAINERS_API_VERSION` 仅用于检查入口向 Maven 传测试客户端版本，非法值退出 2，不写入应用运行环境 |
| 异步批改 | RabbitMQ 用户/口令外置；Compose 将模板中的 GRADING 参数传给 Web/worker；回收阈值覆盖两次模型网络预算，时间参数必须为正 |

这里的组合写法代表各个带前缀的配置键，不是一个包含斜杠的变量名。完整现有绑定以 `application.yml`、Compose 和对应 Properties 为准；新增键必须同步绑定、模板格式说明和负向测试。必需秘密/地址缺失须失败；非敏感安全默认值允许沿用，这是明确的继承例外，不机械执行“所有配置无默认值”。

## 2. 启动与健康

按 [README](../../README.md) 复制模板、私下填写配置，从仓库根目录执行：

```powershell
docker compose --env-file .env up -d --build
curl.exe -f http://localhost:8080/health
```

启动后访问 `/materials`、教师 `/assistants`、`/conversations`；空库默认不开种子就没有演示账号，须按 README 的演示初始化条件处理，不能让检查脚本自动开种子。Compose 依赖健康和用户业务可用是不同检查。

| 范围 | 当前事实 | 本 change 验收目标 |
| --- | --- | --- |
| `/health` | 返回 status、version、UTC time、dependencies | `database/qdrant` 均 up 返回 200/ok，否则 503/unhealthy |
| 模型与动态 MCP | 没有通用无副作用健康协议 | health 明示 `not_checked`，不能宣传所有 AI 能力正常；真实接口另验 |
| 探测时间 | Compose 后端 timeout 已为 10s | 数据库池获取 3000ms，再 `isValid(1)`；Qdrant 独立 1000ms 连接及请求上限、无重试；受控故障 8s 内结束 |
| 版本 | JAR 携带 build-info，支持 APP_VERSION | 部署覆盖受校验，可核对候选/回滚版本 |

health 不运行 Chat/Embedding 生成、不调 MCP 工具、不列教师配置、不写 collection。停止隔离 Qdrant 后返回 503、恢复后重新 200 已由运行验收验证；后续仅在相关实现改动时复测。

## 3. 日志、时限与停机

后端日志一行一个合法 JSON，字段 `timestamp/level/logger/event/requestId`；无请求上下文为 null。请求完成事件增加 `method/path/status/durationMs`；path 使用匹配路由模板，未匹配或未进入 MVC 时为 `/unmapped`，不含 query 值。只接受 `[A-Za-z0-9_-]{1,64}` 的单一 `X-Request-Id`，其他情况生成 UUID；响应头回传，异步线程结束恢复上下文，完成事件不重复。

`JsonLogEncoder` 仅接受请求过滤器和 `GradingLog` 的固定结构化字段，批改事件可含 taskId/status/attempts/durationMs/failureCode。普通日志标为 `application_log`，原消息、参数和堆栈不输出，异常仅保留类名；诊断依靠固定字段，不期待完整异常文本。业务 SSE error 不一定触发容器错误，须核对事件/消息状态，不能将 HTTP 200 当整轮成功。

不写密码、Bearer、提示词/用户正文、完整参数/响应、内部地址、绝对路径或供应商原始异常。对异常记录稳定类别/失败代码，不用堆栈绕过脱敏。Nginx/MCP 基础容器现有日志不宣称已统一成后端应用格式；本 change 的 JSON 编码范围为后端，其他服务扩展需另列范围。

现有检索/模型网关连接/读取 3s/30s，至多一次重试；MCP 为 3s/10s、无重试。MVC 异步上限由读取超时加 10s 得出，Nginx SSE 读取超时 120s。不得随意放大超时掩盖故障；普通 API、检索、模型首帧和完整流分别记录实测耗时，不以 100ms 一刀切。基线不新增性能平台；后续容量测试必须声明请求量/并发、p95 和依赖预算后再定门槛。

材料执行器现为核心 2/最大 4 线程、队列 50；SSE 为核心 4/最大 16、队列 50。保留满载拒绝/恢复契约，不能把队列改成无界来隐藏容量问题。当前没有通用按用户限流或熔断，后续高成本接口须在 change 写并发、频率、模型配额与超额响应，不能声称现状已具备。

最小观察口径为请求量、错误率、耗时和依赖连通：对应请求完成事件计数、按已约定 HTTP/事件状态分类、`durationMs` 分布及 health 固定依赖状态。本轮定义日志字段和人工核验，不额外接指标/告警平台；未来告警必须同时写阈值、责任人和处置动作，不能只写“需要监控”。

**停机例外 OPS-E01：** 当前应用未显式配置完整优雅停机，两类有界执行器不等待全部任务完成。材料依赖持久化状态及重启恢复，SSE 中断按既有失败/重试处理；本轮不宣称在途请求绝不中断。变更停机行为需另写场景和时限；公开长期部署前应完成例如 30s 排空预算、就绪摘流及超时后的处理设计。此次回滚在隔离环境停写/停止请求后进行，不用强杀真实应用演示“成功”。

**检查与处置：** 聚焦健康/日志/异步测试、真实请求 JSON 行解析及脱敏负向验证必须通过；日志串 ID、状态错报、挂起或缺少失败终态时阻断基线验收。

## 4. 发布、回滚和数据变更（按需执行）

发布前确认另一成员审核通过、必要检查通过，涉及数据变更时明确备份与恢复方案。以下回滚步骤是按需操作指南，不是本轮归档的额外验收门槛。首个团队基线的上版可选已验收个人继承提交；候选与旧版均须能从各自代码构建，记录精确提交/标签。禁止使用浮动“最新版”充当回滚目标。

在**专用测试主机或已确认无端口冲突的隔离环境**演练；实际应用不得被此流程停止。两份工作副本使用同一专用 Compose 项目名与演练卷，顺序启动以验证旧版可读新版本产生的数据；候选/旧版私有配置分别核对。若端口被真实服务占用，先准备经评审的测试端口覆盖，不能直接照下面命令运行。

1. 在候选副本确认 `docker compose -p class07-drill --env-file .env config --quiet` 成功，检查项目/端口/卷没有指向真实环境。
2. 执行 `docker compose -p class07-drill --env-file .env up -d --build`；等待健康，核对候选版本、登录和一条本班只读主链。
3. 记录回滚开始时间，在候选副本执行 `docker compose -p class07-drill --env-file .env down`，保留演练数据卷。
4. 进入已核验的旧版副本，核对兼容配置，以同一项目名启动旧应用；旧 health 按旧契约判定，不要求其具有新增字段。检查原用户和材料仍可读，记录耗时与旧版标识。
5. 核对本轮无 schema 变化、两版同为 V1～V7，不执行 Flyway 降级或修改历史迁移；任一步失败则记录失败，不打完成标签。

仅对演练项目执行停止，禁止对真实卷执行删除。恢复候选时沿用已验证流程；实际标签/提交/推送由成员在明确授权后完成。发布记录写版本、变更、配置差异、门禁与回滚结论；机密只保存在私有配置，不进记录。

## 5. 备份、恢复与留存目标

本节是团队策略及后续公开部署目标，当前没有自动备份/恢复服务，不把目标写成已达标。默认 RPO 24h、RTO 2h，备份每日一次且每次 schema 迁移前加一份，保留 14 天；日志和原始报告保留策略见 [安全规范](03-security.md)。改变目标需两人确认并更新运维计划。

维护者在私有、仓库外的受控位置保存 MySQL 一致性备份、同一停写窗口的 uploads、Qdrant snapshot 及必要版本/配置标识。密钥单独受控保管，不能随公开备份说明一起提交；恢复 MCP 密文必须有对应加密密钥。向量从 MySQL 重建是备选，需另外具备嵌入服务、费用与耗时条件，不能当作必然两小时内可恢复。

恢复顺序：创建独立空环境 → 核对备份时间/版本/校验信息 → 恢复 MySQL 与匹配文件 → 恢复兼容 Qdrant snapshot 或受控重建 → 私下注入对应密钥 → 启动 → 核对用户/材料/引用及工具凭据可用性。单纯应用标签回滚不能替代此恢复流程。

涉及持久化结构变更或实际部署风险时，按对应 change 安排恢复验证；未演练不宣称 RPO/RTO 达标。恢复与回滚不作为本轮已验证基线的追加任务。

## 6. 交付收尾

本轮发起方已确认验证通过，另一成员在自己的环境从候选提交启动应用、走通现有功能，并审核实现、文档、已有结果及本次差异中的敏感信息。独立功能复现必须执行，无修改不重跑整套自动测试；有问题则修正并补跑受影响检查。结论记入 `docs/lesson-07/README.md`，通过后由审核成员同步规格、校验、归档并提交，标签按团队需要。

不要求另做规范破坏试验、回滚演练或全历史/镜像扫描；取消项目不记为通过。实际部署、数据清理和远程操作仍按具体目标与权限执行。

Class08 的实际复现与范围另见 `docs/lesson-08/`：worker 关闭材料恢复/Qdrant 初始化；迁移到 V8 后保留数据卷，不执行旧版 V1～V7 示例中的降级假设。重建后端后若 Nginx 仍解析旧地址，可重启同一部署的 frontend；不能据此停止其他项目。
