执行方式：成员 B 授权协作代理对 change 文档和审核规则做技术自审。本节只记录设计/文档一致性检查，**不是实现后的同伴评审，也不能代替代码评审或成员对最终结论的确认**。

| 检查项 | 结果 |
| --- | --- |
| 范围与课程要求 | 作业创建、学生文本提交、202 解耦、事务性发件箱、独立消费者、至少一次、结果唯一约束、有限重试/退避/抖动/死信、状态查询、前端轮询、观测和三条判据均有对应规约 |
| 范围调整 | proposal/design 明确记录 AI 辅助评分提前于原计划，教师复核/改分、完整题库、知识图谱、学习计划和班级分析不在本次 |
| 评分口径 | 模型只给分项判断/证据/解释，服务端按规则确定性计分；结果标注模型辅助，符合 AGENTS 的可解释性约束 |
| 状态机与故障窗口 | `PENDING/RUNNING/SUCCEEDED/FAILED`、原子认领、RUNNING 回收、结果提交后 ACK 前退出、代理不可用补投、重复投递均有场景 |
| 幂等与版本 | 入口按内容哈希/幂等键去重，任务幂等键唯一，结果 `(submission_id, version)` 唯一；明确 MySQL 不使用 `ON CONFLICT` |
| 审核与扫描 | AGENTS 与 04-testing 已加入七类清单、七维评审、逐文件结论、高风险复核、合入顺序和扫描命令；lesson-08 骨架包含三条判据和待填写项 |
| 自包含与泄漏 | 新文档不引用仓库外课件、不包含真实凭据；扫描命令标为待接入，未写成已执行 |
| 发现并修正 | proposal 原写“不支持内容更新后的版本流转”，与 design/spec 的“新内容创建新版本”冲突；已改为支持学生新版本并保留旧结果，仅不含教师复核/改分 |

预评审结论：**文档层面通过，可提交队友评审**。成员 B 已指示按上述建议推进第一部分；本预评审结论作为其授权的技术结论，最终交付仍由成员 B 确认。仍未完成：成员 A 对规则文本和设计的评审、RabbitMQ 选型确认、实现、三条判据、故障/并发验收、扫描执行、交叉评审、归档和版本标签授权。
